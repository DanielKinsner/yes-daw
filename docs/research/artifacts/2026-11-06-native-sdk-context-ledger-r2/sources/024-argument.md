## Object and coexistence rules

Each row records the exact primary excerpt, signature anchor, typed by-value
formals, reference bindings, automatic declarations, materializations, actual
children and return rule. A value formal is an actual object. A reference
binding aliases its existing object and does not clone the referent. Allocator,
base, union, pointer and element members contained in an already qualified
containing object remain inside that object's layout once. An actual separate
empty allocator, fake proxy, tag, predicate or guard is still a separate object;
an empty-looking declaration is neither a zero-size nor one-byte measurement.

For a context c, use the set of distinct source owner identities

    live(c, phase, permitted-order) = enclosing named owners
        union initialized actual formals/materializations
        union active selected own/SDK chain objects.

Its source-object component is the maximum of the sum of qualified sizes over
these sets, across actual sequential phases, alternatives and allowed argument
orders. A missing layout remains its own symbolic sizeof/alignof fact. This is
an incidence equation, not a completed numeric bound. A body declaration union
is an intentionally conservative component, not a claim that all branch locals
or every source row coexist. Loop iterations do not multiply live locals.

Actual call parameter destruction may occur at return or at the end of the
containing full expression as permitted by the language. The latter alternative
is retained explicitly. Actual lexical endings separate source lifetimes; they
do not prove physical stack-slot reuse, stack/spill/shadow space, allocator
reclamation, GC, RSS or process settlement. Returning a named object retains the
no-NRVO alternative and actual caller destination. Returning a parameter cannot
use NRVO. Direct prvalue forwarding does not invent a third result object.
Arithmetic prvalues do not acquire an independently stored object by default.
