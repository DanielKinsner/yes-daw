## Concrete source prerequisite

At run-clock.ps1:298 the fixed runtime literal uses forward slashes. Lines310,
315 and322 compare native paths using OrdinalIgnoreCase against Path.Join of that
literal. Join preserves existing component characters; it does not normalize those
slashes. The normal Windows executable, GetFullPath result and assembly locations
use backslashes. These exact string comparisons therefore reject the intended
controller. The earlier E7361FD1... functional-source acceptance missed this guard.

The exact pinned [Path.cs](https://raw.githubusercontent.com/dotnet/dotnet/e2f47b0110ed922f21a1522da67279133ce28f32/src/runtime/src/libraries/System.Private.CoreLib/src/System/IO/Path.cs)
JoinInternal implementation concatenates component spans and, when needed, one
separator. It performs no internal component rewrite. This matches the public
[Path.Join contract](https://learn.microsoft.com/en-us/dotnet/api/system.io.path.join?view=net-10.0).
No R10 execution is needed to identify this source defect.

The narrow supported repair is a successor whose fixed Windows runtime literal
uses backslashes, preserving its code-unit length and source-action vector. This
adds no GetFullPath call, allocation, new profile choice or weaker comparison.
It still needs exact whole-source/manifest/byte/chunk correspondence review; this
report does not approve an unseen successor or silently change sealed R10. The
defect is a functional prerequisite, not an arithmetic discrepancy in the conditional
positive upper over the proposed source schedule.
