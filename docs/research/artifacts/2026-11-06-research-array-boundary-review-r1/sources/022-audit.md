# Native resource boundary audit

**Recommendation A: finish the controlled source-object/buffer proof under the existing contract, with the runtime limits disclosed.** Do not require a whole-process stack/CRT/RSS certificate as a substitute for that proof. The earlier native-owner R1 remains frozen and HOLD; its six leaves mixed controlled-payload gaps with stronger physical-process questions. This audit splits those questions. It selects no new upper, fit, Data, flag, price, threshold, source revision or execution authority.

Alternative B would promise total physical stack, all CRT startup/EH/TLS/general heap or RSS under 32 MiB. That is a stronger contract, not an interpretation certified here. Do not silently adopt it or declare it satisfied. The remaining narrow ambiguities below stay explicit for independent contract-application review.

## Can the automatic-object part close without physical stack certification?

**Yes, as a controlled source-object upper, conditional on complete source inventory and qualified object sizes.** The identified two Streams/four Texts/one cache coexistence is not alone complete. Retain the other explicit objects in main/run/controls/metadata/build/read/write/query/cost/exception paths, selected-STL local objects, compiler-required real object destinations, nested scopes, no-NRVO alternatives, witnesses and closures. Scalars, embedded members and padding are counted once inside their containing sizeof or as distinct objects; do not duplicate both. A reference parameter does not clone its referent, but any actual reference representation/storage admitted by the selected model is separate from the referent.

The existing source expression with eight Stream sizes, eight Text sizes, one cache and32768 can be a **check against a separately derived source-object envelope**. It cannot supply the derivation or price missing objects. One must first show the actual source large-object counts are within those terms and independently derive the complete other-object bound; only then may one compare it with32768/the existing expression. Unused headroom and an unexplained32768 are not sponsors. This audit does not perform that missing complete derivation, choose a new envelope, or convert the existing assertion into fit.

Compiler spills/home space and the reserve/commit strategy are not additional C++ objects merely because they may hold representations of the same values. Conversely, a source-required temporary or selected-STL object is not a “spill” to be omitted. The controlled-object result must be described precisely as such and must not report a physical stack/working-set bound. The contract's text does not expressly enumerate backend-only stack overhead; this audit leaves that narrow interpretation visible for independent review rather than inventing a new blanket exemption. Nothing here certifies that such physical bytes fit a real process budget.

## True blockers and a noncircular qualification route

The controlled model still needs the complete source/lifetime/object envelope, selected layout/capacity facts it actually uses, any controlled message/path/buffer clones across failure alternatives, exact final identities/binding and simultaneous controller/child settlement join. Those are true remaining obligations. Full primitive CPU, all general CRT startup/EH/TLS/allocator machinery and physical RSS are disclosed unqualified quantities under the existing contract; turning them into mandatory complete numerical vendor proofs would strengthen the task rather than close a missing controlled payload term.

A future **separate-purpose compile-only layout qualification** is attainable without running the Clock or defining its Catalogue: independently author/review a minimal translation unit of the exact nonvirtual POD field/type definitions or rigorously reviewed replicas, public selected types and sizeof/alignof static_assert hypotheses; pin whole source, headers, x64 compiler identity and exact ABI-affecting flags; compile only that purpose unit to an object, with no link, target main, Catalogue data or native execution. Replicas need explicit whole-definition/layout correspondence review, including packing, base/virtual properties and field order. It would establish only the checked compiler layout inequalities. It would not establish complete lifetimes, runtime module behavior, physical frames, whole fit or target GO. A failed hypothesis is preserved and repaired through review, not rounded up after seeing a result.

This paragraph authorizes nothing. Contract5–6 and119–122 still apply: authoring/review and a separate explicit root purpose-compilation GO must precede any compiler invocation. If the required claim instead includes physical stack, a separately authorized exact-object/frame analysis would be a different, stronger qualification task, not a hidden consequence of this source-object method.
