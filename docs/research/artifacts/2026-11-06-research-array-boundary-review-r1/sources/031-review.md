## Narrow meaning and limits

The word “VM” is not a new free category. The supported application is the already selected PowerShell capture/binder/coercion machinery implementing source operations within the existing runtime boundary. Neither source availability nor a CLR implementation language makes an arbitrary visible helper or callback opaque. If the subject were used for that wider claim, it would be unsupported; the subject itself preserves callback/own-loop expansion and C++ expansion.

Compiler source describes implementation choices and semantic distinctions. It does not dictate a new machine-instruction tariff or establish that compiled runtime files match these sources. The complete R2 critic must still check each source form, selected concrete type, caller/callee boundary, setup/result fusion, implicit conversion and actual materialization/lifetime. One conversion O does not mean one byte or one allocation. One array setup does not subsume a separately written ToArray invocation, authored loop or typed parameter conversion.

The R10 `directToArrayCommaReturn` constant group and its no-internal-bulk-byte-CPU note are consistent with this distinction; they are lineage only, not accepted prices or proof of source completeness. Old R10 resource rows already required literal/typed/binder/ToArray/pipeline backings and failed candidates. No old helper/call/phase number is transferred here.

There is no unresolved contract ambiguity requiring a new per-cell tariff for the selected paths. There remain ordinary source-incidence and binary/resource association obligations. Applying the clarification outside those limits would require a new supported decision; it cannot be silently assumed. All prior owner and boundary-audit packets remain unchanged.
